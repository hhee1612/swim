# swim · 游进奥运

手机优先的游泳日记：快捷记录、照片、日历补记、周/月目标、配速趋势、历史筛选与完整备份。

## 使用

- 首页优先展示记录入口、本周次数/距离/天数和周期目标。
- 最近新增游泳的泳馆、泳姿、计时方式会用于下次填写；编辑旧记录不改变这一默认偏好。
- 日历点击日期可补记，已有记录的日期可再记一次；同日多次计为多次游泳、一个打卡日。
- 距离和时间允许留空。配速只统计二者均有效的记录；进步页按泳姿和“含休息 / 净游泳 / 未注明”分别比较。旧记录不会被擅自归类为净游泳。
- 周一为每周第一天，目标从当前周期开始持续生效。修改目标不改变已结束周期的目标值；补记或修正训练记录会相应更新历史成绩。
- 旧版或备份中的未来记录会保留在列表，但不会提前计入当前目标、累计成绩和配速趋势。
- 支持按日期范围、泳姿、泳馆筛选，搜索备注/泳馆。筛选不改变全局累计成绩。
- 编辑保留照片；最近一次删除可在当前页面撤销（含照片）。刷新后撤销入口不保留。

## 离线与更新

首次联网打开并显示“已可离线使用”后，可断网重新打开、记录、上传本机照片、编辑和导出备份。未完成首次缓存前无法保证离线打开。

页面不再依赖外部 CDN 或浏览器内编译；React、样式和应用脚本均随站点提供。新版本会先完整缓存并校验。联网启动、恢复联网和回到前台时自动检查更新；前台运行期间每 5 分钟检查一次。所有本网站页面处于安全状态后自动启用新版并刷新一次。填写记录、保存、处理照片、导入预览、分享及尚可撤销的删除操作会延后刷新，结束后继续。未响应的后台页面不会被当作安全；可保存并关闭其他标签页后继续更新。页脚也提供“检查更新”。缓存仅管理本项目的地址范围。

从旧版首次升级到自动更新机制时，需要先保存当前记录，关闭本网站的所有页面（包括从主屏幕图标打开的页面），再联网重新打开一次。无需清除网站数据。浏览器被关闭或系统暂停后台时无法保证即时更新，回到前台后会继续检查。网站版本更新不会清除 IndexedDB 中的记录和照片，也不会将记录同步到其他设备。

## 数据与备份

数据保存在当前浏览器的 IndexedDB，不上传云端、不自动跨设备同步。记录、照片、目标及偏好作为一个事务保存，写入失败保留原数据。

v3 数据结构兼容 v1/v2 备份和旧 localStorage。升级保留原 localStorage 副本，迁移成功后以 IndexedDB 为准。无法校验的旧数据会显示恢复入口并允许导出旧版原始数据（该诊断文件不是直接可导入的备份）。

完整 JSON 备份含记录、照片、目标及偏好。页面显示最近发起导出的时间、新增未备份记录数，并识别编辑、删除、照片和目标变化；请自行确认下载文件已保存。CSV 不含照片，也不会更新完整备份状态。

导入先预览新增、完全重复、内容冲突的记录：
- 合并按记录编号匹配，不按日期去重；同一备份重复合并不会重复添加。可选择保留本机或使用备份中的冲突版本（含照片）。合并保留本机目标和偏好。
- 替换会覆盖全部记录、照片、目标和偏好，执行前需确认。
- 格式校验或写入失败均保留当前数据。

清除网站数据、移除浏览器或更换设备不会自动保留日记，请定期下载完整备份。

## 开发与验证

运行 `python -m http.server 8000` 并打开 `http://localhost:8000`。GitHub Pages 可直接部署仓库根目录。

使用 Node.js 22 或更新版本，无须安装 npm 依赖：

```sh
node scripts/build.cjs
node scripts/build.cjs --check
node --test tests/core.test.cjs tests/features.test.cjs tests/offline.test.cjs
```

修改 app.jsx、样式或离线资源后需重新构建，并一起提交 app.js 和 sw.js。构建器使用固定版本的本地 JSX 编译器；来源、版本、许可证和校验值见 vendor 目录。编译器仅在构建时使用，不包含在应用离线下载中。

- app.jsx / app.css：界面与交互。
- swim-core.js：数据校验、基础统计、事务存储与旧版迁移。
- swim-features.js：周期目标、趋势、筛选、备份状态与合并。
- offline.js / scripts/service-worker.template.js：离线状态与缓存升级。
